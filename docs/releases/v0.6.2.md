Shared character voices, sound effects that stop when they should, and effects that no longer outlive a jump. v0.6.1 was never tagged; this release carries its changes.

## Added
- `sharedVoicePaths(scenario, voiceId, character2ds, gameCharacters)` lists where a shared `partvoice_` clip can be, from the scenario's appearing characters and the master tables, so a custom resolver can append those candidates after the scenario's own folders. The cue's suffix does not name its pack: `partvoice_96_022_band` can sit in an idol-unit Rin pack. (#29)
- The asset server resolves shared voices the same way, and accepts `scenarioRoot` for prepared `<scenarioId>/scenario.json` files that are not in the catalog yet. (#29)

## Fixed
- Sound effects stop on a jump, on stop and on destroy, including ones still decoding; `SoundPlayMode.Stop` stops the named effect; the listener's SE volume and mute apply to effects that are already playing; a delayed effect is cancelled by a jump. (#29)
- Stopping the BGM stops both crossfade tracks. (#29)
- A scenario effect or prefab background that was still loading when it was stopped, detached, cleared or replaced no longer appears afterwards. (#29)
- A sub character's shared voice pack is found: the master data calls the type `sub_game_character`, and its `characterId` is not a `gameCharacters` id. Rows without an asset name or a unit build no path. (#31)
- A sound effect played before the first tap or click tries its fallback host and its next candidate when a source fails to load, instead of being dropped at the first failure; one that fails on every source warns in the console again. (#31)
- The asset server answers 404 for a shared voice whose scenario file cannot be parsed, instead of throwing. (#31)
